# Security maintenance — 27 November 2026

This change is based on `develop`, after production release v0.1.1. It fixes
available image-library vulnerabilities and adds a release-time security gate.
It does not claim all vulnerabilities are eliminated.

## Image fixes and evidence

Fresh Trivy 0.76.2 scans used an updated advisory database. Baseline app/database
images are the retained 23 November local validation images, not byte-identical
exports of production. Baseline Redis uses the exact deployed pinned digest.

Debian upgrades address Kerberos, zstd and shadow-package advisories. Redis's
unchanged upstream tag still bundled vulnerable OpenSSL/zlib libraries, so the
release now builds a patched Redis image using signed Alpine updates. Redis 7.4,
PostgreSQL 17, pgvector 0.8.6 and their volume formats are preserved. Full compact,
unfiltered findings and image IDs: [inventory](security-2026-11-27.json).

The libxml2 critical finding, CVE-2026-6653, remains unfixed in Debian Trixie.
[Debian's tracker](https://security-tracker.debian.org/tracker/CVE-2026-6653)
lists an upstream fix but no stable-release fix. The application has no arbitrary
SQL/XML interface; that limits exposure but does not repair the library. Remaining
OS findings are retained for review, not suppressed. Do not replace stable system
libraries with incompatible unstable packages merely to reduce scanner counts.
The existing reachability assessments in the release documentation still need
reassessment whenever features or exposure change.

## Preventing recurrence

- Application APT index refresh now fails on repository errors.
- Deployment rebuilds all three images without cached package-update layers.
- CI and deployment scan the actual image IDs/tags, retain complete JSON artifacts,
  and reject HIGH/CRITICAL findings with a vendor-listed fixed version.
- Scanner/network failures abort the deployment. Missing or unsupported reports
  also fail closed. Unfixed findings remain visible; passing this gate is not a
  complete security clearance. Medium/low findings do not block this policy.
- Activation verifies app, PostgreSQL and Redis images exist before stopping the
  app. Redis is transferred and selected by the same immutable release SHA.
- Local Compose builds Redis from the same Dockerfile. Manual production Compose
  use now requires `REDIS_IMAGE` as well as `APP_IMAGE` and `POSTGRES_IMAGE`.

## Validation

- Locked Python runtime audit: no known advisories.
- 1,076 tests passed, 10 skipped with infrastructure enabled.
- 25 UI tests passed; Ruff lint/format and production Compose validation passed.
- Isolated PostgreSQL 17.11 → 17.12 upgrade, vector/HNSW, collation and dump restore passed.
- Isolated Redis AOF upgrade preserved both a string value and a sorted-set queue entry.
- Linux application smoke passed as non-root with read-only root, dropped
  capabilities and no-new-privileges: readiness, policies, 12 MCP tools, worker
  imports and real offline embeddings.
- Six security-gate tests cover fixed/unfixed severities and absent scan results.

Reproduce image checks using `bash deploy/scan-images.sh APP_IMAGE DB_IMAGE REDIS_IMAGE`.
Persistence checks are `python -m deploy.check_database_upgrade DB_IMAGE` and
`python -m deploy.check_redis_upgrade REDIS_IMAGE`.
